# 子Agent：串关优化器 | Parlay Optimizer

> **触发时机：** 所有单场分析完成后
> **输入：** 多场比赛的预测结果（方向/让球/比分/半全场/TTG）
> **输出：** 稳健串、娱乐搏冷串、让球串、混合串方案
> **包含规则：** 规则49、规则55、规则56、串关四类结构（规则47）

---

## 任务说明

串关优化器负责在多场比赛预测完成后，根据各场概率和赔率，生成最优串关组合方案。方法论保持一致性，不因单次结果改变。

## 规则56：串关思路保持一致，娱乐搏冷串可大胆想象

### 稳健串
- 以让球串为主（平局高发轮次让负容错性>方向串）
- 选让负概率>55%的场次

### 娱乐搏冷串
- 以基本面（伤停/战意/状态/交锋/赛制）选场为主
- 可大胆想象极端半全场路径（如胜平、负胜、负平）
- 赔率越高越好
- **连续编号串必含（2026-09-02新增，2026-09-03强化，2026-09-04 v2.7.4精细化）**：混合串至少1个方案包含连续编号场次；娱乐串每个子分类（高赔总进球串/高赔半全场串/半全场混合总进球串/比分串）按场次数量动态新增连续编号方案——**场次≤8场每子分类1个、场次>8场每子分类2个**。连续编号方案须选编号相邻的场次（如001+002、003+004+005），选场以基本面为主。连续编号场次通常为同一比赛日同时段开球，便于用户集中关注

### 方法论一致性原则
- 串关选场方法论不因单次结果改变
- 8月11日132倍命中+本轮高赔半全场串B差一场(80倍)均验证基本面选场有效性

## 规则55：让球串优先

- 平局高发轮次中，串关推荐让球串比重>方向串
- 让负概率>55%的场次优先入选稳健让球串
- **让负=某一方（受让方）不败**：让(f)主负即"受让方客队不败（客队平或赢）"，让(f)客负即"受让方主队不败（主队平或输）"，均命中；当主队让球(-1)时让负=客队平或赢，当客队受让(+f)时让负=主队平或输——统一理解为"博受让方不败"，容错性远优于纯方向串

## 规则49：串关赔率计算方法

- 串关赔率=每场比赛赔率逐场相乘
- 禁止使用估算值或参考值
- 每场赔率必须使用体彩官方数据（MCP优先获取，lottery.gov.cn/zhcw.com降级）
- 串关表须同时展示逐场赔率列和串关赔率列

### MCP串关计算（优先使用）

使用 SportteryAPI MCP 的 `calc_parlay` 工具精确计算串关奖金：

```
server_name: sporttery-odds
tool_name: calc_parlay
args: {
  "legs": [
    { "odds": 1.50, "label": "003主胜" },
    { "odds": 2.30, "label": "008让负" },
    { "odds": 1.80, "label": "010平局" }
  ],
  "passType": "3串1",
  "multiplier": 1
}
```

返回数据包含：
- `bets`: 注数
- `totalStake`: 总投注额（2元×注数×倍数）
- `maxPayout`: 最大奖金
- `maxPayoutCapped`: 是否触及500万封顶
- `byFold`: 各关明细

M串N过关方式查询：

```
tool_name: list_parlay_types
args: { "matches": 4 }  // 查询4场比赛可选的过关方式
```

> **MCP计算结果与体彩官方完全一致**（同源数据+官方M串N规则表），禁止手动估算替代。

## 串关四类结构（规则47）

### 1. 方向串（稳健）
- 从方向概率最高的场次中选2-3场
- 选首选概率>45%的场次
- 平局高发轮次降低方向串比重

### 2. 让球串（稳健，平局高发轮次首选）
- 选让负概率>55%的场次
- 让球串容错性优于方向串（让负=某一方/受让方不败，受让方平或赢均命中）
- 平局高发轮次（欧联次回合/首回合分差≥3球）中让球串比重>方向串

### 3. 混合串（中等风险）
- 方向+让球+TTG混合组合
- 每场选最稳定的维度
- 控制2-3场，避免过多场次
- **连续编号混合串（v2.7.4新增）**：至少1个方案使用连续编号场次（如001+002），场次≤8出1个、>8出2个

### 4. 娱乐串（高赔高风险；规则70：**在原基础上修改——子分类保留、字母方案替换为连续编号方案**）

- 以基本面选场为主（伤停/战意/状态/交锋/赛制）

**结构（规则70，v2.11.1修订，强制）**
1. **原有四个子分类全部保留**：高赔总进球串／高赔半全场串／半全场混合总进球串／比分串（**不得删减**）
2. **每个子分类的原方案只保留 2 个**（A/B），其余字母方案取消
   - 高赔总进球串：总进球串A、总进球串B
   - 高赔半全场串：高赔半全场串A、高赔半全场串B
   - 半全场混合总进球串：混合串A、混合串B
   - 比分串：稳健比分串、搏冷比分串
3. **每个子分类新增 2 个「连续编号」方案**（场次≤8场每子分类1个、>8场每子分类2个）：
   - 高赔总进球串 → **连续编号总进球串①②**（**仍是总进球串，不是比分串**）
   - 高赔半全场串 → **连续编号高赔半全场串①②**
   - 半全场混合总进球串 → **连续编号混合总进球串①②**
   - 比分串 → **连续编号比分串①②**
4. 比分串子分类另含 **单挑比分①②**（单注，不串关）
5. **娱乐串总数 = 4子分类×(2原方案+2连续编号) + 2单挑 = 18 个**

**连续编号段口径（**2026-10-08 口径修订，用户明确纠正：连续编号＝串内编号相邻，不是"用过就不能用"**）**

> 用户原话："连续编号指的是这个串子需要连续编号，而不是用过就不能用，并且比分和半全场是不同串，也不应该算在一起，连续编号不一定要按照第一、第二，也可以从中间4、5这样选取，沉淀到选场逻辑中。"

- **唯一硬约束**：**同一串内各场次编号必须相邻**（001+002、004+005、010+011+012）。串内编号不连续 → 方案无效。
- **允许复用**：同一编号**可跨子分类、乃至同一子分类的另一个方案重复使用**。"用过就不能再用"是**错误理解**；**"跨子分类互不重叠"强制条款已废止**（2026-10-08）。因此 **1-8 号段并非"先到先得"，不再需要为凑够8段而把方案数缩减**。
- **各子分类彼此独立**：总进球／半全场／混合／比分是**四条互不相干的串**，**不合并计算、不共享编号池**——"比分与半全场不应算在一起"。
- **起点自由**：连续编号**不必从001/第一段开始**，可依基本面从**任意相邻编号段**选取（如直接取004+005、010+011）；取号原则是"**该段两场都适配本玩法**"。
- **选段优先级（软性偏好，非强制）**：①段内两场基本面均适配本玩法 ＞②段内号码相邻 ＞③同子分类的两个方案尽量取不同号码段。
- **禁止**：为凑编号而纳入**不适配本玩法**的场次（连续编号是形式约束，不得牺牲选场质量）。

| 连续编号方案 | ①（示例） | ②（示例） |
|:---|:---|:---|
| 连续编号总进球串 | 001+002 | 003+004 |
| 连续编号高赔半全场串 | 005+006 | 007+008 |
| 连续编号混合总进球串 | 009+010 | 011+012 |
| 连续编号比分串 | 013+014 | 015+016 |

（上表仅示范格式，**非强制分配**；实际取号按当天基本面自行选择，**允许跨子分类/跨方案重复同一编号**）

**推演口径（2026-09-15口径改版）**
- **比分类**（稳健比分串、连续编号比分串①②、连续编号混合总进球串①②的比分部分）按**规则67双轨制口径**推演——**推荐众数 `k_rec`（首推方向区间内众数）→ 净胜球带内按联合概率展开候选（≥3个）→ 总进球档位仅作排序加权**；同时产出**分布众数 `k_dist`**（全局众数），**仅用于记录与分歧标注**；**禁止直接取全局概率最高比分**，**禁止使用合并桶（≥3）众数**，**禁止把锚点×档位的交集当唯一比分**，**禁止用 `k_dist` 生成任何比分推荐**
- **让球端**（规则52a）使用**无条件净胜球众数**——与比分端**口径独立、允许不同**（让球须覆盖"首推方向本身可能错"的情形，比分已在锁定方向下注）
- **双众数校验**：第④步校验 **`k_dist` 方向 vs HAD首推方向**——一致→ 标注「众数一致」、可进稳健串；不一致→ 标注「**分布-方向分歧**」，该场**剔出全部正向比分子分类**（含稳健/混合/TOP5/单挑比分①②/连续编号），只能改判搏冷或剔除
- **总进球串／半全场串**的档位与路径按各自子分类的基本面口径（每场独立决定、同串内差异化）——总进球档位按伤停/战意/风格选（伤停集中→低档、大开大合→高档）；半全场路径按伤停/战意选（伤停僵局→平平、客场死守→负负、主场慢热→平胜）

**登记**：连续编号比分串①②属规则67正向流程适用范围，须逐场登记试用台账（`memory/trials/score_parlay_trial.md`）；总进球／半全场／混合的连续编号方案与搏冷比分串**不计入**台账

## 串关选场逻辑

### 比分串选场（规则67 🟡**试用期流程**，优先级高于规则56）
> 状态：试用中；累计≥20场且比分精确命中率≥60%后转正。台账 `memory/trials/score_parlay_trial.md`
> **2026-09-17双轨制 + 2026-10-19赔率逻辑（用户明确要求）**：`k_rec`（方向内众数）为唯一推荐锚点；`k_dist` 仅记录与分歧标注；入选比分须同时满足方向一致、`k_rec`净胜球带、赔率逻辑三约束。

**适用范围**：稳健比分串、混合比分串、TOP5比分串、单挑比分①②、连续编号比分串
**例外**：**搏冷比分串走反向推理**（见下方专节），不适用正向流程

**禁止**直接取模型全局概率最高的比分组串——会出现"首推主胜却买1-1"的方向矛盾；但**同样禁止把锚点锁成唯一比分**（"净胜3球+总进球3球→只剩3:0"，其余比分形同虚设）。必须按五步走：

1. **众数双轨计算**：从同一净胜球分布 `d[k]` 各取一次众数——`k_dist`=全局众数（仅记录/分歧标注，禁止生成推荐）；`k_rec`=HAD首推方向区间内的众数（主胜→k≥+1；平→k=0；客胜→k≤−1，占比≥20%），为唯一推荐锚点。禁止合并桶。
2. **净胜球带展开**：固定净胜 `k_rec`，枚举 `(i, i−k_rec)`（`i ≥ max(0,k_rec)`），按联合概率降序取**前3个**作为候选。
   - 关键恒等式：`总进球=i+j` 与 `净胜球=i−j` **天生同奇偶**；固定 `k_rec` 后可行总进球为 `k_rec`、`k_rec+2`、`k_rec+4`…
3. **总进球档位仅作排序加权**：落入首推总进球档TOP2的候选上调排序、并可裁剪候选数量；**不得**因档位不匹配而删除带内候选。
4. **双众数一致性校验**：`k_dist` 方向 = HAD首推方向 → 进稳健串；不一致 → 标注**「分布-方向分歧」**并**剔出全部正向比分子分类**（可作搏冷或剔除）；**禁止**用 `k_dist` 生成的比分进入任何正向比分子分类。
5. **赔率逻辑校验（2026-10-19新增；胜率优先、赔率第二）**：①先按 `k_rec` 带内模型概率降序选候选（稳健/正向串≥8%），赔率不得改变候选排序，禁止为高赔放弃更高概率比分；②赔率门槛：单挑CRS≥8.00、串关腿≥6.00；③隐含概率（1/赔率）≤模型概率×1.5；④搏冷/娱乐串允许<3%低概率比分（墨菲定律），但不得用其替换稳健串中概率更高的候选；⑤不满足则换场/换比分，**不得回改单场报告TOP5**。

**方案表标注要求**：比分串方案须标注「试用期流程（规则67-双轨制）」及该场**k_dist/k_rec／带内候选TOP3／总进球档／是否分歧／赔率逻辑校验结果**

**登记要求**：每次使用后逐场登记到台账（k_dist及占比／k_rec及占比／带内候选TOP3及概率／首推总进球档／HAD首推方向／是否分歧／实际比分／判定），**漏登则该场不计入试用统计**

**搏冷比分串（反向推理，不适用上方五步）**
- 搏冷串本质是打与锚点方向相反的结果，套用正向流程会自相矛盾，故改用**反向推理**：
  1. **先定冷门剧本**：明确冷门方向＋可验证成因（强队残阵／主帅危机／交锋魔咒／多线分流／新援磨合／升班马铁桶）
  2. **剧本内推演比分**：按剧本逻辑给比分（"强队主场被逼平"→1:1、2:2；"弱队客场爆冷"→1:2、0:1；"主队崩盘"→1:3），比分必须与冷门方向一致
  3. **赔率择优**：从剧本内比分中优先选**不在模型TOP5内**的比分以获取高赔

### 比分最高赔串选场（规则56关联，**仅作辅助**）

### 半全场串选场
- 优先选半全场路径独立性强的场次（如大热门vs残阵，路径确定性高）
- 避免在同一串关中放入两场都有"补时绝平"风险的杯赛首回合
- 杯赛首回合可考虑加入"胜平"路径覆盖（主队领先被追平）
- **高赔半全场串C/D（非纯搏冷）**：以历史战意、韧性、数据选场，参考可能出现的负胜/胜负/胜平等高赔反转路径，为真实可支撑的剧本，非无差别追冷

### 混合串选场
- 方向+让球+TTG/半全场跨玩法组合，路径多样化（规则61）
- **混合串C/D（非纯搏冷）**：同样基于历史战意、韧性、数据选场，参考高赔反转路径（负胜/胜负/胜平）搭配 TTG 档位，而非纯方向冷门拼盘

### 让球串选场
- 让负概率>55%的场次优先
- 后防危机场次（≥3人缺阵）→让胜概率低→让负优先入选
- 平局高发轮次→让球串比重提高
