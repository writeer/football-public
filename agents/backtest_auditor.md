# 回测报告审核子Agent (Backtest Auditor)

> **触发时机：** 回测教训管理器完成后（第9步后）、回测报告输出给用户前
> **核心职责：** 对照回测模板和规则逐项审核回测报告，不通过则打回重做
> **前置步骤：** 第9步回测教训（`agents/backtest_lessons.md`）生成完整回测报告文件
> **职责边界：** 本子Agent只负责"检查"，不负责"生成"。回测报告生成由 backtest_lessons 执行

---

## 可用MCP工具（football_mcp 直调接口 · 规则78）

> 回测核验时用于**独立核对赛果与数据**的直调接口（命令在仓库根目录执行，stdout 恒为 JSON）：

| 核验用途 | 服务 | 工具 |
|:---|:---|:---|
| 历史比赛结果+赔率（核验比分/半场比分/命中判定） | `mcp-sports-hub` | `footballdata_uk_get_matches`（`league` 如 `E0`，`season` 如 `2425`） |
| 赛果二次核对（与归档JSON比对） | `football-charts` | `get_results` |
| 长期命中率参照（公开模型 track record） | `football-charts` | `get_track_record` |

- 自检：`node football_mcp/bin/football-mcp.mjs self-test`；清单见 `football_mcp/README.md`
- **纪律**：核验结论须标注来源+时间；第三方数据与体彩/官方赛果冲突时以官方为准并标注矛盾（规则29/37）

## 一、审核流程

```
Step 1：模板结构完整性检查 → Step 2：让球与必填维度检查 → Step 3：数据一致性校验
→ Step 4：命中判定准确性检查 → Step 5：格式规范检查 → Step 6：串关回测完整性检查
→ Step 7：模拟盘结算完整性检查（规则82） → 全部通过 → 审核通过 / 任一不通过 → 打回重做
```

## 二、审核清单（逐项打勾，任一未通过则打回）

### A. 模板结构完整性（对照 zhihu_backtest_template.md）

| 序号 | 检查项 | 通过标准 | 不通过处理 |
|:---:|:---|:---|:---|
| A1 | 标题格式 | 【回测】日期（星期）回测报告 \| 核心看点摘要 | 修改标题 |
| A2 | 报告说明 | 包含赛后回测报告说明 + 赛前分析报告预告 | 补充 |
| A3 | 风险提示 | "回测结果仅供参考，历史命中不代表未来表现" + 理性购彩提示 | 补充 |
| A4 | 开场总结 | 2-3句话：总场次、方向命中率、最大亮点/翻车 | 补充 |
| A5 | 总览表 | 含13列：编号/对阵/赛事/预测方向/实际方向/命中/让球/让球命中/总进球/进球命中/半全场/半全场命中/比分TOP5命中 | 补充缺失列 |
| A6 | 总览备注 | 1-2句话命中率汇总 | 补充 |
| A7 | 逐场回测 | 每场含：赛果行 → 预测回顾表（5行）→ 点评 | 补充缺失部分 |
| A8 | 命中率统计表 | 含6行：方向(首选+次选)/方向(仅首选)/让球(首选+次选)/总进球TOP2/半全场TOP3/比分TOP5 | 补充缺失行 |
| A9 | 串关回测表 | 按类别分组，"类型"列使用分析报告子分类名称（方向串/让球串/混合串/总进球串/高赔半全场串/半全场混合/比分串），每方案含各场结果+串关命中+估算赔率 | 补充 |
| A10 | 关键发现 | 3条发现，每条含标题+展开说明 | 补充 |
| A11 | 待改进 | 3条以上改进点 | 补充 |
| A12 | 写在最后 | 从 `templates/closing_remarks.md` 选取方案 | 补充 |

### B. 让球与必填维度检查

| 序号 | 检查项 | 通过标准 | 不通过处理 |
|:---:|:---|:---|:---|
| B1 | 让球行存在（逐场） | 逐场回测表含"让球"行，显示让球首选/次选 + 实际让球方向 + 命中 | 补充让球行 |
| B2 | 让球列存在（总览） | 总览表含"让球"列（让球数+方向）和"让球命中"列 | 补充让球列 |
| B3 | 让球行存在（统计） | 命中率统计表含"让球(首选+次选)"行 | 补充让球统计行 |
| B4 | 让球首选/次选显示 | 总览表让球列显示"让(X)首选/让(X)次选"；逐场表显示"让(X)首选 / 让(X)次选" | 补充次选 |
| B5 | 方向首选/次选显示 | 总览表方向列同时显示首选和次选（如"主胜/平"）；逐场表也同时显示 | 补充次选 |
| B6 | 实际比分显示 | 总进球列实际值显示具体比分（如"2-1"）而非进球数（如"3"） | 修正显示 |

### C. 数据一致性校验

| 序号 | 检查项 | 通过标准 | 不通过处理 |
|:---:|:---|:---|:---|
| C1 | 总览表 vs 逐场 | 总览表首选/次选/命中/让球与逐场回测表一致 | 修正不一致项 |
| C2 | 命中率 vs 逐场统计 | 命中率统计表的数字与逐场命中标记逐项核对一致 | 重新统计 |
| C3 | 让球命中准确性（强制公式计算，禁止凭直觉） | 逐场按公式重新计算让球结果，与报告中记录的让球结果比对：净胜球=主队进球-客队进球；**调整后净胜=净胜球+让球数（主让为负、主受为正）**；调整后净胜>0=让胜，=0=让平，<0=让负。速查：让(-1)→净胜≥2=让胜/净胜=1=让平/净胜≤0=让负；让(-2)→≥3/=2/≤1；让(+1)→净胜≥0=让胜/净胜=-1=让平/净胜≤-2=让负；让(+2)→≥-1/=-2/≤-3。任一场让球结果计算错误则整份报告打回 | 重新计算全部让球结果 |
| C7 | 让球首选是否符合规则52a | ±1盘场次让球首选须与"基本面净胜球众数"对应（主队净胜=1→让(-1)让平；客队净胜=1→让(+1)让平）；让球首选/次选须三选覆盖含让平，不得仅列让胜+让负 | 补正让球首选/次选 |
| C4 | 方向命中准确性 | 实际方向等于预测首选→✅首，等于次选→✅次，否则❌ | 修正判定 |
| C5 | 概率加总 | 每场主胜+平+客胜≈100%（±2%误差） | 重算 |
| C6 | 串关赔率检查 | 串关回测表中赔率为赛前分析报告原始赔率，非回测时赔率 | 修正赔率 |

### D. 命中判定准确性

| 序号 | 检查项 | 通过标准 | 不通过处理 |
|:---:|:---|:---|:---|
| D1 | 方向命中标注 | 用✅首/✅次/❌标注，与实际方向核对 | 修正标注 |
| D2 | 让球命中标注 | 用✅首/✅次/❌标注，与实际让球方向核对 | 修正标注 |
| D3 | 总进球命中标注 | 实际进球数在预测TOP2中→✅，否则❌ | 修正标注 |
| D4 | 半全场命中标注 | 实际半全场在预测TOP3中→✅，否则❌；总览列标注实际赛果 | 修正标注 |
| D5 | 比分TOP5命中标注 | 实际比分在预测TOP5中→✅，否则❌ | 修正标注 |
| D6 | 串关命中标注 | 串关方案中各场全部✅→串关✅，否则❌ | 修正标注 |

### E. 格式规范检查

| 序号 | 检查项 | 通过标准 | 不通过处理 |
|:---:|:---|:---|:---|
| E1 | 比分横杠格式 | 全文比分用横杠（如 `2-1`），无冒号格式（`2:1`） | 全局替换 |
| E2 | 半全场两字格式 | 全文半全场用两字格式（`胜胜`/`平负`等），无斜杠格式（`胜/胜`） | 全局替换 |
| E3 | 无分割线 | 全文无 `---` 分割线 | 删除 |
| E4 | 总进球术语 | 全文使用"总进球"，不使用"TTG"缩写 | 全局替换 |
| E5 | 命中符号 | 命中用✅，未命中用❌，不使用其他符号 | 修正 |
| E6 | **评级阈值合规**（2026-09-14新增，来源：9-13回测评级阈值被自定义改写） | 命中率统计表的"评级"列必须**严格按** `templates/zhihu_backtest_template.md`【评级标准】判定：**100%→完美 / 75-99%→优秀 / 60-74%→良好 / 45-59%→一般 / <45%→较差**。逐行按命中率数值落入的区间核对评级文字，**严禁自定义阈值**（如误用85%/70%/55%/40%导致评级整体高估一档） | 按模板【评级标准】重判全部评级 |

> **E6 判定示例（对照用）**：87.5%→优秀（非完美）、83.3%→优秀、79.2%→优秀、58.3%→一般（非良好）、41.7%→较差（非一般）、29.2%→较差。任何与上表区间不符的评级即打回。

### F. 串关回测完整性

| 序号 | 检查项 | 通过标准 | 不通过处理 |
|:---:|:---|:---|:---|
| F1 | 串关引用基准 | 串关回测以赛前分析报告原始推荐为基准，引用分析报告 | 补充引用 |
| F2 | 让球串回测 | 串关回测表包含赛前分析报告中的让球串方案（稳健让球串/价值让球串） | 补充让球串回测 |
| F3 | 单表格式+类型对应 | 串关回测为**单张表格**（与模板一致），不得拆分为多个子表。"类型"列值必须与分析报告串关章节的**子分类名称**一一对应：方向串/让球串/混合串/总进球串/高赔半全场串/半全场混合/比分串（不得统称"娱乐串"）。方案顺序与分析报告一致 | 合并为单表+修正类型列 |
| F4 | 各场结果 | 每方案写出原始预测场次内容，括号内标注实际结果 | 补充实际结果 |
| F5 | 串关汇总 | 表后单行汇总（与模板一致）：`> 串关命中n/N个方案，命中率X%。` + 按7个子类分别统计命中率 + **区分稳健方案（方向串／让球串／混合串）与娱乐串（总进球串／高赔半全场串／半全场混合／比分串）两组分别统计命中率**（2026-09-14补充，来源：9-13回测漏分组统计） + 翻车主因说明 | 补充汇总与分组统计 |
| F6 | 串关方案完整性+类型一致 | 赛前分析报告中的**全部**串关方案均在回测中出现，逐方案对照不得遗漏。清点方法：打开分析报告串关思路章节，逐方案→在回测报告中查找对应行（方案名+场次+赔率三匹配），缺失任一方案即不通过。同时检查"类型"列值与分析报告子分类名称一致（如分析报告"高赔半全场串"子节下的方案，回测类型列不得写"娱乐串"） | 补充缺失方案+修正类型 |
| F7 | JSON-报告一致性 | 回测JSON的 `parlays` 数组包含全部串关方案，且每个方案的 matches/results/hit/odds_est 字段与回测报告中的表格行一一对应 | 修正JSON或报告 |
| F8 | 串关各场命中标注准确性 | 逐方案逐场验证：各场实际结果与回测JSON `results` 中记录是否一致；让球结果按公式重算（净胜球=主队进球-客队进球；**调整后净胜=净胜球+让球数（主让为负、主受为正）**；调整后净胜>0=让胜，=0=让平，<0=让负）；半全场/比分/总进球与赛果核对 | 修正标注 |
| F9 | 串关命中判定准确性 | 串关方案中各场全部✅→串关✅，任一场❌→串关❌；hit字段与判定结果一致 | 修正判定 |

## 四、审核原则

1. **一票否决**：任一检查项不通过，整体打回重做
2. **让球优先**：让球数据缺失是最常见的回测报告缺陷，BT1-BT4为最高优先级检查项
3. **就事论事**：指出具体问题位置和修正建议，不笼统说"质量不行"
4. **对照模板**：所有结构检查以 `templates/zhihu_backtest_template.md` 为唯一基准
5. **不编造数据**：缺失数据标注"信息缺失"，禁止编造让球方向或命中结果
