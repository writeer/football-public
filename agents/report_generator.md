# 子Agent：报告输出器 | Report Generator

> **触发时机：** 串关优化完成后（第6步后）
> **输入：** 前6步全部输出——已验证伤停/新闻/天气（步骤1-2）、联赛修正系数（步骤3）、基本面修正（步骤4）、6维度推荐+置信度（步骤5）、4类串关方案（步骤6）
> **输出：** 完整知乎风格分析报告（Markdown文件）+ 预测JSON归档
> **包含规则：** 规则15、规则36、规则53、规则60、规则61（已失效）、**规则70**、**规则71**、**规则72（空场·第一级别）**、规则62-F、**规则74（大小球·总进球合并行）**、**规则76（跨联赛等级差行）**

---

## 任务说明

报告输出器负责将前6步的分析结果按照知乎模板组装为完整报告。这是审核前的最后一步生成工作——报告必须在此步骤中完整生成，然后交由报告审核器（第8步）逐项审核。

## 可用MCP工具（football_mcp 直调接口 · 规则78）

> 报告术语与口径核对可通过仓库内 `football_mcp/` **直接调用**（命令在仓库根目录执行，输出恒为 JSON）：

| 用途 | 服务 | 工具 |

| 指标口径统一（xG/PPDA/控球口径，避免术语混用） | `football-docs` | `get_metric` `list_metrics` |

- 自检：`node football_mcp/bin/football-mcp.mjs self-test`；清单见 `football_mcp/README.md`
- **纪律**：报告中引用任何第三方 MCP 数据，必须标注**来源+获取时间**（规则26/29）；赔率一律以体彩官方为准（规则15）
- **赛事性质提示（2026-10-15）**：跨联赛赛事（欧战/杯赛/友谊赛）出现某国球队时，**只标注"(XX联赛)"来源，不得写"XX联赛平局上修/降级/主场权重"等联赛特化**；此类场次的联赛行写"赛事等级 + 双方所在联赛等级差"（规则76），不写国内联赛特点

## 核心原则

**主要推荐以基本面和模型概率为准，市场赔率仅做分歧参考（规则28强化，2026-08-24用户明确）。**
- 报告中的推荐依据以基本面分析（伤停/战意/状态/交锋/赛程）和模型概率为第一优先级
- 市场赔率（Shin校准/体彩赔率）仅用于检查"模型vs市场"分歧，不作为推荐依据
- 融合权重中市场来源（Shin 8%）已控制在最低，基本面因素（15%）和模型（50%）占主导
- 报告展示时：推荐表只列模型概率，不列赔率（规则60）；市场分歧仅在"模型vs市场行"中标注，不参与推荐定论

**生成与审核分离：** 本子Agent只负责"生成"，不负责"审核"。审核由独立的 `report_auditor.md` 执行。

## 报告生成流程

```
Step 1：加载模板 → Step 2：填充总览表 → Step 3：逐场填充
→ Step 4：填充综合推荐/搏冷/串关 → Step 5：执行格式化规则（53/60/61）
→ Step 6：生成预测JSON归档 → Step 7：输出报告文件
```

### Step 1：加载模板

- 加载 `templates/zhihu_article_template.md` 作为报告骨架
- 从 `templates/closing_remarks.md` 随机选取一个方案用于"写在最后"段落
- 确认报告日期、星期、场次数量

### Step 2：填充总览表

- 从步骤5输出中提取每场的：编号、对阵、首选方向+概率、次选方向+概率、置信度
- 总览表格式：编号 | 对阵 | 首选 | 次选 | 置信度（5列，不显示赔率，规则60）
- 总览备注：1-2句话总结本轮关键特征
- **首选/次选以模型概率排序为准**，市场赔率方向不参与首选/次选排序。仅在模型与市场分歧>15%时，在逐场点评中标注"市场分歧"

### Step 3：逐场填充

每场比赛按模板结构依次填充：

1. **场地天气行**（来源：步骤1信息收集）——球场名+城市+草皮类型+容量+**场地状态 `stadium_status`（规则72·第一级别：空场/部分关闭/中立场必须显式标注）**+温度+天气+风力+影响评估
2. **基本面段落**（来源：步骤4基本面分析）——首回合/近期状态核心信息，1-2句话
3. **身价对比段落**（规则36，必填）——双方总身价+倍数关系+1句解读
4. **伤停段落**（来源：步骤2信息审核核查）——核心缺阵球员+位置+类型+人数
5. **模型概率行**（来源：步骤5模型计算）——融合概率三方向+lambda值。**主要推荐依据**：融合概率决定首选/次选方向，lambda值反映进球预期。市场赔率（Shin方向）仅在该方向与模型**严重分歧（>15%）** 时标注分歧说明，不写入推荐表
6. **推荐表**（来源：**规则62-F——常规场次比分TOP5由“参考模型的推演”输出**；比分串另按规则67三约束）——比分TOP5/半全场TOP3/HAD/HAFU/大小球·总进球/半场比分（**6行2列**）。**单场报告不得套用比分串的净胜球/赔率筛选逻辑**；推演候选须有模型概率支撑，允许<3%低概率比分（墨菲定律）
7. **置信度行**——置信度等级+1-2句话理由
8. **点评**（1-2句话，聚焦核心风险或判断）

### Step 4：填充汇总与串关

1. **综合推荐汇总表**（7列：编号/对阵/胜平负首选/次选/让球首选/次选/总进球）——**推荐以模型概率+基本面分析为准**，市场热度仅标注在分歧备注中
2. **搏冷推荐汇总表**（搏冷场次表+市场过热场次列表）——**搏冷推荐以基本面异常信号为触发条件**（如基本面明显指向主胜但市场大量押注客胜），而非单纯追市场反向
3. **串关思路**（来源：步骤6串关优化）——方向串/让球串/混合串/娱乐串四类

### Step 5：执行格式化规则

在此步骤中依次执行以下规则的格式化处理：

#### 规则FMT：基础格式规范（强制执行，生成时逐项检查）

> 以下格式规则来自模板 `templates/zhihu_article_template.md`，生成时**必须逐项检查**，不依赖后续审核修正。审核器会逐项复核（见审核清单G节）。

1. **比分横杠格式**：所有比分用横杠格式（如 `2-0`、`1-1`、`0-2`），**禁止用冒号**（`2:0`、`1:1`）。适用范围：比分TOP5行、半场比分行、推演段落、串关比分串行、JSON的score字段
2. **半全场两字格式**：所有半全场结果用体彩标准两字格式（`胜胜`/`胜平`/`胜负`/`平胜`/`平平`/`平负`/`负胜`/`负平`/`负负`），**禁止用斜杠**（`胜/胜`、`平/负`）。适用范围：半全场TOP3行、推演段落、串关半全场串行
3. **不使用分割线**：知乎编辑器不友好，报告全文**禁止出现 `---` 分割线**（包括场与场之间、章节之间）。用空行分隔即可
4. **模板章节完整性**：以下章节在模板中定义，生成时**必须全部包含**，缺失即视为未完成：
   - 总览（含总览表+总览备注）
   - 逐场分析（每场完整8个部分）
   - 综合推荐汇总表
   - 搏冷推荐汇总表（含市场过热场次列表）
   - 串关思路（方向串/让球串/混合串/娱乐串 四类齐全）
   - 娱乐串子类齐全（**规则70结构**：**四个子分类必须齐全**——高赔总进球串（总进球串A/B + 连续编号总进球串①②）／高赔半全场串（A/B + 连续编号①②）／半全场混合总进球串（混合串A/B + 连续编号①②）／比分串（稳健比分串＋搏冷比分串＋连续编号比分串①②＋单挑比分①②）；另含风险提示、选场核心原则、串关数量规则；**不得删减任一子分类**）
   - **娱乐串法甲排除（规则71）**：娱乐串中**不得出现法甲场次**（**大巴黎场次除外**）——统计当天非PSG法甲场次N，**N<3或N=3→纳入0场**、**N>3→纳入1场**（上限1场，且只能出现在1个方案）；连续编号段跨法甲须**整体换段**；娱乐串开头须标注 `已按规则71排除法甲：当天非PSG法甲N场 → 纳入X场`。**串关思路章节不受此限**
   - 本轮规律（3-4条）
   - ☕ 写在最后（从 `templates/closing_remarks.md` 随机选取）
5. **串关数量规则**：场次≤5场以二串一为主；6-8场二串一+三串一并重；>8场以三串一为主
6. **娱乐串结构规则（规则70，v2.11.1修订，强制；"在原基础上修改，不是重构"）**：①**原有四个子分类全部保留**（高赔总进球串／高赔半全场串／半全场混合总进球串／比分串，**不得删减**）；②每个子分类**原方案只保留2个**（A/B），其余字母方案取消；③每个子分类**新增2个「连续编号」方案**替代被取消的字母方案，且**连续编号方案属于原玩法本身**——总进球串下仍是总进球串、半全场串/混合串同理，**只有比分串下的才是连续编号比分串**；④**连续编号口径（2026-10-08修订）**：**唯一硬约束＝串内编号相邻**（如001+002、004+005）；**同一编号允许跨子分类/跨方案重复使用**（"用过就不能再用""跨子分类互不重叠"均已废止）；**各子分类彼此独立、不共享编号池**；**不必从001起选**，可从任意相邻段起取；**禁止为凑编号而纳入不适配本玩法的场次**（示例格式：总进球001+002/003+004、半全场005+006/007+008、混合009+010/011+012、比分013+014/015+016，**非强制分配**）；⑤总数 = 4子分类×(2原方案+2连续编号) + 单挑比分①② = **18个**。**生成时逐项检查；缺失任一子分类、或退回v2.11.0的"10个方案（仅连续编号比分串）"结构，视为格式不通过**
7. **风险提示与免责声明**：报告开头必须包含风险提示（本轮具体风险）+ 免责声明；报告末尾必须包含总风险提示
8. **比赛风格必须具体（禁止空话，2026-10-30用户明确批评）**：比分推演的"比赛风格"行必须写出**双方阵型、压迫/防守方式、主要进攻手段（边路/中路/定位球/反击）**，例如"博德4-3-3高位压迫+边路三角短传；维京4-3-3直接长传+两翼速度"；**严禁**写成"{{主队}}主场体系 vs {{客队}}客场体系"这类无信息量的套话（用户原话："这个不是和没说一样吗？我发现你最近很爱用这个"）。
9. **"写在最后"必须使用方案库原文（强制约束，禁止自定义）**：
   - "## ☕ 写在最后" 章节内容**必须**从 `templates/closing_remarks.md` 的8个方案（C/D/E/F/G/H/I/J）中随机选取一个，**整段原文照抄**
   - **禁止**自行编写结尾话术、禁止拼接多个方案、禁止修改方案文字
   - 每次生成时从方案C/D/E/F/G/H/I/J中随机选一个（不可每次都选同一个），将方案标题（如"## ☕ 写在最后"）和正文整段插入
   - 方案文本以 `templates/closing_remarks.md` 文件内容为准，审核器G5逐字校验

#### 规则FMT-8：比分方向一致性（强制执行，2026-09-01新增）

> **背景**：003西汉姆vs狼队推演写"狼队客场反客为主"但比分给2-1（主队2客队1=主胜），方向完全写反。根因：生成时未校验比分方向与推演场景描述是否一致。

**所有比分一律使用主队-客队格式（Home-Away），必须与推演场景方向一致：**

1. **推演场景描述主胜**（"主队先取得进球"/"主场气势"/"主场苟赢"等）→ 比分必须主队>客队（如2-1、3-0、1-0）
2. **推演场景描述客胜**（"客队反客为主"/"客场偷分"/"客队状态好"等）→ 比分必须客队>主队（如1-2、0-2、1-3）
3. **推演场景描述平局**（"僵局"/"闷战"/"对攻平局"等）→ 比分必须主队=客队（如1-1、0-0、2-2）
4. **TOP5方向覆盖检查**：若某方向概率≥15%，TOP5中必须包含至少1个该方向的比分。例：客胜20%→TOP5必须有至少1个客胜比分（如1-2、0-1）；若TOP5全为主胜或平局比分但客胜概率≥15%，视为方向不自洽，必须修正
5. **适用范围**：推演段落、比分TOP5行、半场比分行、串关比分串行

#### 规则FMT-10：比分串方向优先（规则67，🟡**试用期流程**，2026-09-12新增）

> 状态：试用中（暂定使用）；累计≥20场且比分精确命中率≥60%后转正为必备流程。台账 `memory/trials/score_parlay_trial.md`

**生成"#### 比分串"子节时，禁止直接取模型全局概率最高的比分组串**（会造成方向与比分自相矛盾）；**同样禁止把锚点锁成唯一比分**（"净胜3球+总进球3球→只剩3:0"）。必须按**规则67双轨制四步**生成：

1. **众数双轨计算**：从同一净胜球分布各取一次众数——**分布众数 `k_dist = argmax d[k]`**（全局最大值、不合并桶；桶上界=矩阵阶数−1）**仅用于记录与分歧标注**；**推荐众数 `k_rec`** = 在 HAD首推方向区间内取最大值（主胜→`k≥+1`／平→`k=0`／客胜→`k≤−1`）
2. **净胜球带展开**：固定净胜 `k_rec`，枚举 `(i, i−k_rec)`（`i ≥ max(0,k_rec)`），按联合概率降序取**带内候选TOP3**（候选必须≥3个）
3. **总进球档位仅作排序加权**：落入首推总进球档TOP2的候选上调排序、可裁剪候选数量；**不得**因档位不匹配而删除带内候选
4. **双众数一致性校验**：`k_dist` 方向 = HAD首推方向 → 标注「众数一致」、可进稳健串；不一致 → 标注「**分布-方向分歧**」并**剔出全部正向比分子分类**（含单挑比分①②）

> **关键恒等式**：`总进球=i+j` 与 `净胜球=i−j` **天生同奇偶**——这是数学恒等式，不是过滤条件；固定 `k_rec` 后可行总进球只能是 `k_rec`、`k_rec+2`…（旧流程"按档位跳过奇偶不符者"每场只剩2个可行解，属缺陷，已废止）

**适用与例外（2026-09-17双轨制改版）**：
- **正向流程适用范围**：稳健比分串、混合比分串、TOP5比分串、单挑比分①②、连续编号比分串
- **例外——搏冷比分串走反向推理**：搏冷串打的是与首推方向相反的结果，**不适用**上述四步，改为「先定冷门剧本（方向＋可验证成因）→ 剧本内推演合理比分 → 赔率择优（优先取不在模型TOP5内的比分）」，并标注「**反向推理（冷门剧本：XXX）**」
- **口径（2026-09-17双轨制）**：比分端**推荐锚点 `k_rec` 采用方向内众数、分布众数 `k_dist` 仅作记录**；**让球端（规则52a）维持无条件净胜球众数**，两者口径独立、允许不同（让球须覆盖"方向本身可能错"，比分已在锁定方向下注）

**输出要求**：
- **逐场点评后必须输出「净胜球众数」行**：`> **净胜球众数：** 分布众数 **{{k_dist}}**（{{占比%}}）｜推荐众数 **{{k_rec}}**（{{占比%}}）｜{{众数一致 / 分布-方向分歧}}`
- 比分串方案说明中须标注「**试用期流程（规则67-双轨制）**」，并列出该场「分布众数／推荐众数及各自占比／带内候选TOP3／首推总进球档／是否分歧」
- **正向流程**所选比分**必须与净胜球推荐众数 `k_rec` 所在带一致**（`k_rec` 为主胜时不得出现1-1、0-0）；**搏冷比分串除外**（其方向即冷门方向，须与冷门剧本一致）
- **「分布-方向分歧」场次禁止进入任何正向比分子分类**（含单挑比分①②）；分歧场次只能改判搏冷或直接剔除，**不得**因"没有候选"而降格使用分歧场次
- 连续编号比分串同样按本流程生成，不得按概率排序拼凑
- 搏冷比分串须与正向比分串**分别成列**，不得混用
- 生成后须将本场登记信息交由总控写入试用台账（搏冷串不计入台账）

## 与报告审核器的衔接

报告输出完成后，自动进入第8步报告审核（`report_auditor.md`）：

**报告输出器与审核器的职责边界：**
- 报告输出器：执行规则（生成报告、执行格式化、填充模板）
- 报告审核器：检查规则（对照模板审核、一票否决、打回重做）
