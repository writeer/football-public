### Layer 0：联赛诊断（每场必做，决定主力分布族）

**VMR过离散检测：**
```
VMR = 联赛历史进球方差 / 联赛历史场均进球
VMR ≤ 1.05 → 标准泊松可用
VMR 1.05~1.2 → DC模型（主力）
VMR > 1.2 → 负二项分布替换泊松（必须）
VMR > 1.5 → 同时使用负二项 + 广义泊松对比（德甲/荷甲标志）
```

**零膨胀检测：**
```
联赛0-0率 < 5% → 不需要零膨胀
联赛0-0率 5%~10% → ZIP/ZINB可选
联赛0-0率 10%~15% → 推荐启用ZIP/ZINB
联赛0-0率 > 15% → 必须启用ZIP/ZINB + Hurdle对比（意甲标志）
```

> 联赛VMR和0-0率数据从 `memory/leagues/{league}.json` 的 statistics 字段获取。

### Layer 1：xG校准（每场必做，决定λ准确度）

```
★ xG校准是λ基准的核心输入，跳过xG校准的模型计算视为无效

xG校准公式：
  λ_修正 = λ_原始 × (xG_实际 / xG_预期)

偏离分析：
  xG实际 > 实际进球 → 球队运气差/前锋把握能力差 → 预计未来回归均值（进球会增加）
  xG实际 < 实际进球 → 球队运气好/超常发挥 → 预计未来回归均值（进球会减少）
  偏离>30% → 状态不可持续信号，lambda向联赛均值收缩

数据来源：
  两队近10场xG（实际值vs预期值），搜索 "{球队} xG" 获取
  优先来源：Understat / FBref / Opta
```

### Layer 5：赔率校准（每场必做）

**Shin模型（首选，8%权重）：**
```
迭代求解z（内幕交易者比例，通常0.02~0.05）：
  P_i = √(z + (1-z) × (1/o_i)²) / Σ √(z + (1-z) × (1/o_j)²)
z越大 → 冷门概率向上修正越多
```

**校准方向（基于历史修正经验）：**
- 大球概率下修5-10%（模型通常高估大球）
- 平局概率上修3-5%（模型通常低估平局）
- 0-0比分概率上修（ZIP/ZINB未启用时）

### Layer 6：蒙特卡洛模拟（每场必做，不可跳过）

```
基于DC/负二项进球分布，模拟N=10000场：
1. 从DC/负二项采样主队进球 ~ Dist(λ_home)
2. 从DC/负二项采样客队进球 ~ Dist(λ_away)
3. 统计：主胜/平/客胜计数、总进球分布、比分频率、让球盘覆盖
4. 计算各结果占比作为蒙特卡洛概率
5. 统计稳定性指标（CV变异系数）
```

## 规则67：比分串净胜球锚点独立计算 + 带内展开——模型计算端（2026-09-12新增；**2026-09-15口径改版**，🟡**试用期规则**）

> 状态：试用中；累计≥20场且比分精确命中率≥60%后转正为必备流程。台账 `memory/trials/score_parlay_trial.md`

**每次分析必须额外产出以下三项【结构化输出】**（供串关优化器与总控使用）：

**产出1：双轨净胜球众数（分布众数 `k_dist` + 推荐众数 `k_rec`）**
```
取净胜球分布 d[k]（DC/NB/ZIP 比分矩阵按 k = i − j 对角聚合），各取一次众数：
  分布众数 k_dist = argmax_k d[k]                                  # 全局最大值，仅记录
  推荐众数 k_rec  = argmax_{k ∈ 方向区间} d[k]                      # 唯一推荐锚点
    主胜 → k ∈ {+1, +2, +3, …} ；平 → k = 0 ；客胜 → k ∈ {−1, −2, …}
```
- **`k_dist` 仅用于台账记录与第④步分歧标注，禁止用于生成任何比分推荐**；**`k_rec` 是唯一的带内展开锚点**
- **不得**把 k≥3 合并为"≥3"桶（两个众数均须逐 k 独立取值）；**不得**乘报告 HAD 方向概率重锚定
- 桶上界 = 矩阵阶数 − 1（矩阵阶数由 `MAXG` 决定；**极端实力差场次强制 n≥16**，避免截断误差）
- 输出格式示例：`分布众数：0（23.5%）｜推荐众数：+1（22.7%）｜一致：否`
- **改版依据（L127）**：`k_dist` 是"单点最大值"、方向是"区间聚合"，两者数学性质不同；强队胜势分散在多根柱、平局概率全压在 k=0，故 `k_dist` 在"方向明确但优势分散"的场次上系统性输给平局（9-16 实测 17 场中 12 场即 70.6% 与方向矛盾）

**产出2：带内候选TOP3（含联合概率）**
```
固定净胜 = k_rec，取 (i, i − k_rec)，约束 i ≥ max(0, k_rec) 且 i − k_rec ≥ 0
按 Mx[i][i−k_rec] 降序取前 3 个作为「带内候选」
```
- 输出格式示例：`带内候选：1-0(13.1%) > 2-1(9.5%) > 3-2(2.3%)`
- 带内候选不足3个时扩展到 |k − k*| ≤ 1 的相邻带，并标注偏移
- 首推总进球档位用于给候选**排序加权**（落入首推档者上调），**不得**用于删除候选

**产出3：首推总进球档位TOP2（降级为排序参考）**
```
取TTG分布（DC/NB修正后）概率最高的2个进球数作为「首推总进球档位」
输出格式示例：`首推总进球档位：2球(25.7%) / 3球(21.9%)`
```

**关键恒等式（务必理解，L115来源）**：`总进球 = i+j` 与 `净胜球 = i−j` **天生同奇偶**——这是数学恒等式而非过滤条件；固定 `k*` 后可行总进球只能是 `k*`、`k*+2`、`k*+4`… 旧流程"按档位概率降序跳过奇偶不符者"因此每场只剩 2 个可行比分、首选唯一，所谓比分TOP5/其他比分全是装饰（"众数净胜3球+总进球3球→只剩3:0"）。**已废止该做法。**

**禁止**：①不得把"全局概率最高的比分"作为下游比分串输入（去掉锚点即失效）；②不得使用合并桶众数；③不得把"锚点×档位"的交集当唯一比分输出。

**与规则52a的关系（2026-09-17双轨制起口径独立）**：**比分端**产出 `k_dist`（记录）+ `k_rec`（推荐），**让球端**维持**无条件净胜球众数**并按规则52a判定表输出让球首选/次选——两者**口径独立、允许不同**：让球端须覆盖"首推方向本身可能错"的情形，比分端已在锁定方向下注、故用方向内众数。第④步校验 **`k_dist` 方向 vs HAD首推方向**：不一致→标注「分布-方向分歧」，该场剔出全部正向比分子分类。

**例外：搏冷比分串走反向推理**：搏冷比分串**不适用**本正向流程（其本质是打与锚点方向相反的结果，套用正向流程会自相矛盾），改走「先定冷门剧本（方向＋可验证成因）→ 剧本内推演合理比分 → 赔率择优（优先取不在模型TOP5内的比分）」，并标注「反向推理（冷门剧本：XXX）」；**搏冷比分串不计入规则67试用台账**。

## 规则9：伤停折算精细化

不得使用全队统一系数机械折算，必须区分：
- 核心终结点缺阵 → 进攻lambda下修
- 中场组织者缺阵 → 进攻组织能力下修
- 防守球员缺阵 → 防守lambda（对手进攻）上修

### 规则9a：残阵战意反弹修正（2026-08-15新增，来源L012）

伤停≠必然变弱。以下场景lambda下修幅度减半，甚至不上修：

1. **伤停集中在非核心位置**（如后卫线缺阵但前锋完整）→ 进攻lambda下修幅度减半
2. **赛季前2轮伤停**（替补球员为争取首发位置更拼命）→ 整体lambda下修幅度减半
3. **保级队/争冠队伤停**（战意极强，残阵反而激发斗志）→ lambda下修幅度减半或不上修
4. **战术调整型伤停**（教练因伤停改为更保守阵型→防守更稳→总进球下修而非进攻lambda下修）

> 来源：2026-08-14回测，002瓦萨(TPS 4人停赛)实际1-3惨败、004波鸿(7人残阵)客场1-0赢球、006埃夫斯堡(2前锋+门将伤停)实际3-0大胜。三场共同规律：残阵球队全部激发战意反而赢球，机械下修lambda导致方向预测错误。

## 规则72：空场 / 中立场主场加成覆盖 —— 模型计算端（2026-09-29新增，第一级别）

> 上游：`agents/information_verifier.md` 规则72（审核部分）输出的 `home_advantage_override`；本规则为模型端执行口径。

### 覆盖参数速查表

| `stadium_status` | 主场加成处理 | 客队处理 | 其他强制 |
|:---|:---|:---|:---|
| `正常` | 按联赛配置（含规则68英超下调等） | 正常 | — |
| `空场` | 乘数**置 1.0** | 不变 | **禁止判定为"碾压局"**（`crush_match = false`）；置信度降一级 |
| `部分关闭`（比例≥30%） | 乘数**折半** | 不变 | 置信度降一级 |
| `部分关闭`（比例<30%） | 乘数 **×0.85** | 不变 | — |
| `中立场/移师` | 乘数**置 1.0** | **免客场惩罚**（不施加客场下修） | 置信度降一级 |

### 执行口径
1. `home_advantage_override` 存在时，**替换**（非叠加）联赛JSON与联赛特化规则给出的 `home_advantage_factor`
2. 空场方**不得**再叠加三强主场加成、主场状态加成等任何主场类修正
3. **碾压场判定（`crush_match`）须在撤回主场加成后重新评估**——空场方不享受主场加成，碾压前提不成立
4. 空场导致方向首选概率跌破 **45%** 时，须在输出中标注"置信度再降一级 + 次选必含平局"
5. 计算结果须在预测JSON中留痕：`stadium_status`、`home_advantage_override`、`crush_match`、`confidence_impact`

### 来源案例
- 2026-08-09 周日020 本菲卡 vs 维塞乌：空场未处理 → λ主3.70、`crush_match=true`、比分TOP5全为大比分 → 实际 2-2（爆冷）
- 2026-09-28 周一006 罗马尼亚 vs 波黑：空场未处理 → λ主1.35（含主场加成）、主胜48.5% → 实际 2-4；撤回加成后 λ主应为 1.00-1.08、主胜 37.5-40.1%

> 本子Agent仅执行上修参数并标注重叠项；**规则65是否触发、冲突如何裁决、是否跨场次强制执行，由总控（主协调器）最终拍板**——总控对每一场走查4项触发条件（身价差≥2倍/λ差≥0.8/让球盘≥1球/排名差≥8或积分差≥10），任一满足即强制上修lambda与TTG档位，不靠子Agent自觉（呼应L040）。

> 联赛分析器（`league_analyzer.md` 规则66）从联赛JSON读取 `ht_draw_rate` 并产出半场平局层级分类后，由模型计算引擎执行以下半场lambda修正与半全场概率调整。针对不同联赛半场平局率差异巨大（日职53.4% vs 挪超32.5%），统一使用0.45系数导致半场比分与半全场预测系统性偏差。

### 执行顺序（在规则22-REF/规则65之后，半全场概率矩阵计算时）
```
Step 1: 从联赛分析器获取半场平局层级分类（基于联赛JSON ht_draw_rate）
Step 2: 按层级确定 lambda_ht 系数（0.38/0.42/0.45/0.48）
Step 3: 计算半场泊松矩阵 → lambda_ht = lambda_full × 系数
Step 4: 生成半场比分TOP3
Step 5: 按层级执行半全场概率修正（"平平"上修或"胜胜"/"负负"上修）
Step 6: 重新归一化半全场概率矩阵
```

### 与其他规则的交互（总控裁定）
> 本子Agent仅执行修正参数并标注重叠项；**规则66最终触发判定由总控拍板**——总控对每场走查联赛 `ht_draw_rate` 字段，按上述框架强制修正半全场与半场比分，不得跳过。
- **与规则63（单关平局上修）**：韩职/日职半场平局上修 + 单关全场平局上修可同时执行（作用于不同维度：规则63修正全场平局概率，规则66修正半场lambda与半全场概率）
- **与规则65（大球上修）**：大球上修作用于全场lambda，半场平局修正作用于半场lambda与半全场概率，二者维度不同可共存
- **与规则5（补时进球）联动**：低半场平局联赛（英冠）下半场后段和补时进球集中，半场无平不意味着全场无平

## 规则76：跨联赛等级差校准——模型计算端（2026-10-14新增，用户明确要求）

> 本规则为模型计算端的**等级差校准执行**，等级差判定（赛事等级/两队联赛等级/队内位置/等级差）由联赛分析器产出【结构化输出】（见 `league_analyzer.md` 规则76）。**最终触发判定与档位微调由总控拍板。**

### 校准参数（跨联赛赛事，等级差≥1档即激活）

| 校准项 | 等级差≥1档 | 等级差≥2档（跨级对阵） |
|:---|:---|:---|
| **低等级方 λ** | ×0.90-0.95 | 再×0.90（上限累计×0.85） |
| **爆冷概率** | 低等级方主场爆冷=系统性风险，评估不得低于同等级内部冷门标准 | 同上+高等级方客场叠加规则72场地/空场修正 |
| **让球盘** | 不强制 | 等级差≥2档+身价差≥2倍：防深盘浅赢（联动规则52a让平路径） |
| **大小球** | 依基本面落规则74六档 | 两极化：强队轮换磨阵地→小球；弱队防线崩盘→大球 |

### 执行顺序（在规则22-REF λ修正之后、规则65大球上修之前）
```
Step 1: 判定是否跨联赛赛事（两队来自不同国内联赛）→ 否：跳过
Step 2: 从联赛分析器接收等级差判定（赛事等级/两队L档/等级差/校准建议）
Step 3: 按上表对低等级方 λ 打折（等级差≥1档×0.90-0.95；≥2档再×0.90，上限×0.85）
        ★ 高等级方客场远征不额外打折（规则27-B赛程密度已覆盖）；人工草/严寒等场地因素照常修正（009博德案例）
Step 4: 爆冷先验：跨等级对阵低等级方主场爆冷概率不得压低于同等级内部冷门标准
Step 5: 让球盘：等级差≥2档+身价差≥2倍 → 输出"浅赢"风险标注（供规则52a让平路径参考）
Step 6: 大小球：输出两极化倾向 → 交规则74六档落档
Step 7: 提交校准结果【结构化输出】；**规则76最终触发判定、档位微调由总控拍板**——总控对每场跨联赛走查等级差判定与校准落地，不得跳过
```

### 执行口径要点
- **等级差≠胜负预判**：校准只是先验修正，不得用于"压死"低等级方——博德闪耀（挪超L3）主场3-1曼城（英超L1）为反例；爆冷概率必须保留
- 与规则65（大球上修Tier1/2/3）**两套分档口径**：规则65分档服务大球上修（lambda_total+0.3/0.4），规则76分档服务等级差校准（低等级方λ打折）——同一场可同时触发，作用于不同侧
- 与规则36（身价差）**并行不替代**：身价差=市场估值维度，等级差=竞争环境维度
- **国内数据不可直接跨联赛套用**：低等级方对高等级对手的场均进球/失球需先打折再入模型（联动跨联赛xG失真：五大联赛系数1.0、欧洲二级0.85-0.90）

### 来源案例（2026-10-14 周三欧冠8场实测）
- 006 LASK(奥超L3) vs 利物浦(英超L1)：等级差2档跨级+身价17.5倍 → λ打折+爆冷先验，模型客胜77.8%

## 规则63：单关信号—平局上修（2026-08-19新增，用户明确要求）

> 当竞彩(主任)在某场比赛的胜平负(HAD)玩法开放**单关**（无需串关、可单场单独投注）时，视为市场结构信号，**平局概率上修**。

> **适用范围（单关特化，2026-08-19用户明确 + v2.3.4流程变更）：本规则仅在主任开胜平负单关时适用。未开放胜平负单关的场次，本规则一律不执行，不做任何平局上修。** 单关状态以 single_match 字段确认为准，该字段**由用户赛前告知填充（v2.3.4起，不再自动检测）**——用户明确告知某场开单关才置true，未告知一律false。

### 判断逻辑（票面结构 ≠ 实时赔率）

| 要素 | 说明 |
|:---|:---|
| 什么是"单关" | 竞彩对该场HAD开放"单场投注"，区别于必须2场以上过关的普通场次 |
| 信号含义 | 主任通常对**悬念较大、主客比分较均衡、或需吸引资金平衡盘口**的场次开放单关；此类场次平局倾向常被模型低估 |
| **适用前提（铁律）** | **必须已确认该场开放HAD单关（single_match=true）。未开单关→规则63不启用，平局不做上修** |
| 数据来源 | **用户赛前告知（v2.3.4起，不再自动检测）**；用户明确告知某场开单关，未告知一律视为未开 |
| **L029例外** | 双残阵/基本面强烈指向对攻分胜负的场次，即使开单关，平局上修不适用（弃平局改大球+方向，呼应L029） |

### 修正方式（幅度8%~15%，可按场次性质量档）

- 只对被确认开放单关的场次执行：**平局概率上修8%~15%**（在模型融合概率基础上，如平局26%→上修至约34%~41%）
- 幅度分档（依据平局与首选的距离）：
  - **平局落后首选≤10pp**（悬念大）→ 按上沿 **+12%~15%**
  - **平局落后首选10~20pp**（相对接近）→ 按中段 **+10%~12%**
  - **平局落后首选≥20pp**（悬殊）→ 按下沿 **+8%**（聊胜于无，重点转投让球/比分）
- 上修来源为平局+幅度，主胜/客胜概率按原比例等比例压缩
- 具体幅度仍可依回测校准

### 执行检查清单（每场必做）

1. ☐ 该场HAD是否开单关（single_match字段）：**由用户赛前告知填充，不再自动检测**？
2. ☐ **若未开放单关（single_match=false）→ 规则63跳过，平局不做任何上修**
3. ☐ 若开放单关，是否按"平局与首选差距"档位执行 +8%~15% 上修？
4. ☐ 上修后主胜/客胜是否已按比例压缩，确保三概率和为1？
5. ☐ 单关上修是否与规则16（赛季平局率高）/规则54（杯赛平局暴风眼）叠加执行（可叠加，平局累计上限+18%）？

> 来源：2026-08-19用户洞察。开放单关的HAD场次平局被系统性低估，需在模型输出阶段显式上修。幅度2026-08-19由默认5%上调至8%~15%（按平局与首选差距分档，累计叠加上限平局+18%），可依回测校准。

## 规则52a：让球首选由基本面净胜球推演决定（2026-09-12新增；**2026-09-13口径回退为「无条件净胜球众数」**）

> **核心**：让球首选 = **无条件净胜球众数**所对应的让球方向；**净胜一球概率最大 → 首推让平**。
> **口径回退（2026-09-13，用户裁决："让球使用旧口径"）**：让球首选**使用无条件净胜球众数**（不先锁定胜负方向）。2026-09-12曾统一为「方向内条件众数」，经9-12全轮30场回测证伪后回退：
>
> | 口径 | 让球首选命中 | 命中率 |
> |:---|:---:|:---:|
> | **无条件净胜球众数（现行）** | 11/30 | **36.7%** |
> | 方向内条件众数（已废弃） | 4/30 | 13.3% |
>
> **证伪原因**：条件化丢掉了"首推方向本身可能错"的概率，导致让平被过度首推（30场中26场锚点落±1/±2），而实际让平仅4场（13.3%）。
> **统一口径的适用范围（2026-09-13，用户明确）**：条件化口径**仅用于「胜负方向 → 总进球 → 推演比分」链（规则67）**；**让球使用无条件口径，其余推荐流程（让球/半全场/串关等）一律不变**。让球锚点与比分锚点**相互独立、允许不同**。

### 步骤1：做无条件净胜球推演
1. 取**无条件**净胜球分布（Skellam/DC 输出的 `net_dist`）的**众数**作为**净胜球锚点**（**不**先锁定胜负方向）
2. 输出格式：`无条件净胜球众数：k（占比 x%）`
3. **禁止**：①直接取模型Skellam让球矩阵概率最高项；②直接取市场最低赔项；③改回已被证伪的"方向内条件众数"（**本处是让球端，条件口径只属于比分端**）

### 步骤2：对照判定表定首选与次选

| 无条件净胜球众数 | 让(-1)主让1球 | 让(+1)主受1球 |
|:---|:---|:---|
| 主队净胜≥2 | 让胜（首选） | 让胜（首选） |
| 主队净胜=1 | **让平（首选）** | 让胜（首选） |
| 平局(0) | 让负（首选） | 让胜（首选） |
| 客队净胜=1 | 让负（首选） | **让平（首选）** |
| 客队净胜≥2 | 让负（首选） | 让负（首选） |
| 让球数n（±2及以上） | 按 `调整后净胜=净胜球+让球数` 判定：>0让胜／=0让平／<0让负 | 同左 |

### 步骤3：次选与三选覆盖（强制）
- ±1盘**必须三选覆盖**让胜/让平/让负：首选取判定表结果，次选取剩余二者中概率较高者，并在输出中明确列出让平
- **禁止**仅在"让胜+让负"二选中取舍；让平不得因"模型Skellam概率排第三""市场赔率最低""总进球档位高"被排除
- 深盘(让-2及以下/让+2及以上)同样保留让平路径

### 步骤4：模型矩阵只做校核
- Skellam让球矩阵用于**校核**，不用于决定首选；与基本面推演冲突时**以推演为准**（与规则62-F一致）
- 若模型让球概率与推演结论方向相反，需在输出中标注"模型-推演分歧"并保留推演首选

### 计算参考
- 让球结果换算（唯一正确公式）：`调整后净胜 = 净胜球 + 让球数`（主让为负、主受为正）；>0 让胜 / =0 让平 / <0 让负
- 让平基础出现率不低：2026-09-11回测±1盘样本15场中让平4场(27%)
- 低进球预期场次（总进球TOP1≤2球）是让球判断高风险区，此类场次优先纳入让平路径（样本量小，仅作方向性提示）
- **口径演进记录（2026-09-13）**：9-12赛前以条件化口径推演001（主胜方向内净胜众数1球）与002（客胜方向内净胜众数1球），两场恰与实际让平吻合，据此在 **n=2** 样本上把让球口径统一为条件化；**次日30场回测即证伪**（条件化4/30=13.3% vs 无条件11/30=36.7%），已按用户裁决**回退为无条件口径**。方法论：凡进规则层的口径变更，n=2不足以支撑，须先做最小样本验证（L097）

### 复盘教训（L092）
001京都不死鸟(让+1净胜-1)、009雷恩(让-1净胜1)、011塞维利亚(让-1净胜1)三场实际均为让平，三场让球首选/次选（受模型矩阵概率与市场低赔引导）全部未含让平，三场全失。其中009/011赛前总进球TOP1仅2-3球，基本面已明确指向"1球小胜"，却未首推让平。
